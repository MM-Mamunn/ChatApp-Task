
Maintain `PROJECT_PROGRESS.md` at the project root as the authoritative record of implementation progress.

**Every time you make changes to the project, update `PROJECT_PROGRESS.md` before finishing your task.**

Record a brief, accurate summary of:
- What was implemented or changed.
- The relevant files created, modified, or deleted.
- Any configuration, dependency, database, or environment setup performed.
- Verification or tests performed and their results.
- Known issues, incomplete work, or remaining tasks.

Update the existing progress file rather than creating additional progress files. Preserve previous progress records and update task statuses accurately.

Only mark a step as completed after its implementation has been verified. If a step is partially implemented or verification fails, clearly document its actual status.

Keep the progress report concise and factual. Do not record planned work as completed, and do not claim that tests passed unless they were actually run successfully.

This requirement applies to every implementation step, bug fix, configuration change, and other project modification. **Never finish a task without updating `PROJECT_PROGRESS.md` to reflect the actual changes made.**
